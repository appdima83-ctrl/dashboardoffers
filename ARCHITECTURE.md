# Дашборд ProfitCash: архитектура и разработка

Документ описывает, как устроен дашборд партнёрской программы LeadCash (ProfitCash), какие данные и откуда он берёт, как работает фронтенд, как его запускать и деплоить, и как он развивался.

- Репозиторий: `Alexdanry/dashboardoffers`, ветка `main`.
- Хостинг: Render (веб-сервис Node), автодеплой с `main` или ручной Deploy latest commit.
- Назначение: одна страница статистики партнёра: хосты, клики, конверсии, заработок, баланс, офферы, страны, трафик по приложениям, аналитика приложений (Firebase/GA4) и статусы приложений в Google Play.

---

## 1. Обзор

```
┌───────────────────────────── Браузер / PWA ─────────────────────────────┐
│  public/index.html  (один файл: HTML + CSS + JS, без сборки)             │
│  public/sw.js       (service worker только для «На экран Домой»)         │
└───────────────▲──────────────────────────────────────────────────────────┘
                │ HTTPS, cookie pc_session (HttpOnly)
┌───────────────┴──────────────── server.js (Node ≥18) ────────────────────┐
│  вход по паролю · маршруты /api/* · статика public/ · кэш в памяти       │
│                                                                           │
│   ga.js      play.js      demo.js                                         │
└──┬────────────┬────────────┬─────────────────────────────────────────────┘
   │            │            └─ демо-данные, если нет AFFISE_API_KEY
   │            └─ Google Play Developer API + публичные страницы Play + GCS-отчёты
   └─ Google Analytics 4 Data API (аналитика Firebase приложений)
 
   server.js → Affise Partner API (api-profitcash.affise.com): статистика, баланс, офферы, курсы
```

Ключевые решения:

- **Нет зависимостей.** Чистый Node: `http`, `fs`, `crypto`, глобальный `fetch`. `package.json` содержит только `start`.
- **Секреты только на сервере.** Ключ Affise, ключи Google и пароль не попадают в браузер. Фронтенд получает уже готовые данные.
- **Фронтенд без сборки.** Один `public/index.html` (около 1400 строк), статические ресурсы лежат рядом.
- **Данные всегда живые.** Запрос при открытии страницы, по кнопке «Обновить» и при возврате на вкладку (больше 60 с). На сервере короткий кэш в памяти, чтобы не упираться в лимиты API.

## 3. Бэкенд (`server.js`)

### 3.1 Запуск и конфигурация

- `.env` читается вручную (без `dotenv`). Реальные переменные окружения приоритетнее файла.
- Порт: `PORT` (по умолчанию 3000). Пароль: `DASH_PASSWORD`. Если пароль не задан, вход невозможен (по замыслу).
- Часовой пояс отчётов Affise: `TIMEZONE` (по умолчанию `Indian/Kerguelen`, как в кабинете).

### 3.2 Авторизация

- Вход: `POST /login`, поле `password`. Сравнение через SHA-256 и `timingSafeEqual`.
- Ограничение: 5 попыток в минуту с одного IP, затем ответ 429.
- Сессия: cookie `pc_session`, `HttpOnly`, `SameSite=Lax`, срок 30 дней. Токен = `срок.HMAC(SESSION_SECRET)`, на сервере ничего не хранится. Если `SESSION_SECRET` не задан, генерируется случайный при старте (сессии сбрасываются после перезапуска).
- Без сессии: страницы перенаправляются на `/login`, API отвечает 401. Публично открыты только манифест, иконки и `sw.js`.

### 3.3 Маршруты API

| Маршрут | Что отдаёт |
|---|---|
| `GET /api/config` | Конфигурация интерфейса и список офферов |
| `GET /api/stats?from&to&offer&country&currency` | Главная страница: ряды по дням, офферы, страны, баланс, «сегодня» |
| `GET /api/sources?from&to` | Страница «По приложениям»: трафик по меткам `sub1` |
| `GET /api/play` | Статусы приложений в Google Play |
| `GET /api/ga/<app>?days=7|30|90` | Аналитика конкретного приложения (Firebase/GA4) |
| `POST /login`, `GET /login`, `/logout` | Вход, форма, выход |

Даты проверяются регулярным выражением `YYYY-MM-DD`. Ошибки апстрима превращаются в понятные сообщения (`Affise отклонил ключ`, `ошибка 429` и т. п.).

### 3.4 Интеграция с Affise

Базовый адрес `https://api-profitcash.affise.com`, заголовок `API-Key`. Используются методы:

| Метод | Для чего |
|---|---|
| `/3.0/stats/custom` | Основная статистика со срезами `offer`, `country`, `sub1`, `day` (комбинации срезов) |
| `/3.0/stats/getbydate` | Ряд по дням для графика и таблицы |
| `/3.0/balance` | Баланс партнёра по валютам |
| `/3.0/currencies` (запасной `/3.0/admin/currency`) | Курсы валют |
| `/3.0/partner/offers` | Каталог офферов: страны и выплаты |

Сопоставление полей с кабинетом (сверено):

- хосты = `traffic.uniq`, клики = `traffic.raw`;
- конверсии = `actions.total.count` (включая отклонённые);
- «Заработано» = `actions.total.revenue`;
- отклонённые конверсии = `actions.declined.count` (поле `declined`);
- статусы дохода: `confirmed`, `pending`, `hold`, `declined`.

Служебные функции: `aget` (запрос с повтором при 429 и 5xx, таймаут 20 с), `allPages` (постраничная выгрузка), `cached(key, fn, ttl)` (кэш в памяти, по умолчанию 15 с).

Кэши: курсы валют 1 час, каталог офферов 10 минут, статистика 15 с, «сегодня» 15 с, страница «По приложениям» 30 с, аналитика приложения 20 с, Play 10 с.

### 3.5 Валюты и баланс

- Все суммы приводятся к доллару по курсу Affise (`rate` = единиц валюты за 1 USD). Выплаты офферов в других валютах пересчитываются тем же курсом.
- Баланс берётся из поля `available` ответа `/3.0/balance` («доступно к выводу»). Причина: поле `balance` в какой-то момент расходилось с кабинетом, а `available` совпадало по евро и росло вместе с подтверждёнными конверсиями. Если `available` пусто, берётся `balance`.
- В ответе: `total.USD` (всё в долларах), `parts` по валютам (сумма, курс, эквивалент в долларах).
- Нюанс: баланс меняется в реальном времени. Скриншот кабинета, открытый давно, показывает меньшую сумму, чем API.

### 3.6 Фильтр по стране

`/api/stats` принимает `country` (ISO-2). Значение добавляется как `filter[country]` во все запросы Affise (ряд по дням, офферы, страны, «сегодня»), поэтому пересчитываются карточки, график, офферы и прирост за сегодня. Ключ кэша включает страну.

### 3.7 Прирост «за сегодня»

Отдельный запрос по текущей дате в часовом поясе кабинета возвращает словарь `offersToday` (по `id` оффера: хосты, клики, конверсии, отклонённые, сумма). Он питает зелёные плашки `▲ +N` и красные `✕ +N` (отклонённые) в списке офферов и вкладке «По приложениям».

### 3.8 Метки `sub1` и страница «По приложениям»

Идея: приложение добавляет в ссылку оффера `&sub1=<метка>`, и трафик, клики и доход можно разложить по приложениям.

- Данные: `stats/custom` со срезами `sub1`, `sub1+offer`, `sub1+country`, `sub1+offer+country`.
- Метки приводятся к нижнему регистру.
- `SRC_APPS` = `метка=пакет Google Play` (иконка, название и страна берутся из Play). Значение по умолчанию в коде:
  `pautang=com.navo.navo_calculator, prestomin=com.prestomin.dinerorapido, mpowa=com.emergencyloanguide.app, wonga=com.wonga.otpusk_planner, unifi=com.unifi.financecalc, kwik=com.kwikloanguide.app`.
- Метки, перечисленные в `SRC_APPS`, показываются на странице всегда, даже без трафика (карточка с нулями).
- `SRC_META` = `метка=название|страна|ID свойства GA4` для приложений, которых нет в Google Play. Через него подтягиваются страны пользователей из Firebase.
- Важно: переменная `SRC_APPS` в Render перекрывает значение по умолчанию из кода. После добавления новой метки в код её нужно дописать и там.
- Скрытые офферы: `HIDE_OFFERS` (по названию или id, по умолчанию скрыт `Finpug.co.za [CPL]`).

## 4. Аналитика приложений (`ga.js`)

Вкладки Wonga, Mpowa, Mepresta, Unifi, Kwik, Prestomin показывают данные Firebase Analytics через Google Analytics 4 Data API.

- Авторизация: сервисный аккаунт Google (OAuth по подписанному JWT). Ключ задаётся `GA_SERVICE_ACCOUNT_JSON`, `GA_SERVICE_ACCOUNT_FILE` или парой `GA_CLIENT_EMAIL` + `GA_PRIVATE_KEY`. Разбор приватного ключа устойчив к кавычкам, запятым и переносам. Для отдельных приложений можно задать свои ключи с суффиксом `_<APP>`.
- Аккаунту нужна роль «Читатель» на свойстве GA4.
- `APPS` описывает приложения: `propertyId` или `findByName` (свойство ищется по отображаемому имени, равному идентификатору Firebase-проекта). У Unifi свойство общее с другим приложением, поэтому отчёты ограничены потоками (`streamIds`).
- Отчёты за период (7, 30 или 90 дней): активные пользователи 1/7/28 дней, версии приложения, страны, события, реальное время и «сегодня» (для зелёных приростов). Есть режим `GA_MOCK=1`.
- Функция `countriesBetween` отдаёт страны пользователей для сравнения на странице «По приложениям».
- Замечание: у Kwik нет событий `offer_*`, это вопрос кода приложения, а не дашборда.

## 5. Google Play (`play.js`)

Вкладка «Google Play» показывает, в каком состоянии приложения в магазине.

- Источники: Android Publisher API (только чтение, сервисный аккаунт приглашён в Play Console), публичные страницы магазина (названия, иконки, сравнение с консолью), отчёты установок в GCS (несколько аккаунтов разработчика), данные GA (даты версий).
- Статус Production определяется автоматически: опубликовано, на проверке или обновление на проверке. Проверка Google в API недоступна, поэтому есть ручные пометки.
- Закрытый тест: срок 14 дней при 12+ участниках, остаток дней показывается в карточке. Напоминание о релизе новой версии каждые 5 дней.
- Ручные переменные: `PLAY_PACKAGES` (список `пакет:название`), `PLAY_FLAGS` (rejected | blocked | review), `PLAY_RELEASED` (дата релиза), `PLAY_HIDE` (скрыть дорожку), `PLAY_TEST_START` (старт теста или `wait`), `PLAY_COUNTRIES` (страна приложения).
- Повтор запроса один раз при сетевой ошибке `fetch failed`.

## 6. Фронтенд (`public/index.html`)

### 6.1 Страницы и маршрутизация

Маршрут задаётся хэшем в адресе.

| Хэш | Страница |
|---|---|
| `#` | «Партнёрка»: карточки, график, баланс, офферы, страны, таблица по дням |
| `#sources` | «По приложениям»: карточки приложений с метриками и офферами |
| `#play` | «Google Play» |
| `#wonga`, `#mpowa`, `#navo`, `#unifi`, `#kwik`, `#prestomin` | Аналитика конкретного приложения (в меню группа «Приложения») |

Функция `route()` переключает видимые блоки, заголовок, подзаголовок и активный пункт меню. У каждой страницы свой загрузчик (`load`, `loadSrc`, `loadPlay`, `loadApp`) и свой рендер.

### 6.2 Главная страница

- **Четыре карточки:** хосты, клики, количество офферов (конверсии), заработано. Под каждым значением плашка прироста за день. Счётчики анимируются при загрузке.
- **Блок «Заработано» (карты):** стопка из двух карт на картинке пользователя. Первая USD, вторая EUR. Сверху суммы в валюте, внизу «Итого» в долларах и расшифровка по валютам (сумма × курс = доллары). На карте USD плашка прироста за день.
- **График «Динамика по дням»:** SVG, четыре серии (клики, хосты, заработано на правой шкале в долларах, конверсии на своей шкале). Монотонная кубическая интерполяция, адаптивное сглаживание по плотности точек, светлая полупрозрачная плашка-подсказка при наведении, легенда под графиком.
- **«Офферы по результату»:** переключатель Конверсии / Сумма / Клики / Хосты. В режимах «Клики» и «Хосты» показываются только офферы с приростом за сегодня. Для каждого оффера флаги стран, иконки приложений-источников, колонка «К выплате», доля от общего итога.
- **«Трафик по странам»:** кольцо по хостам, ряд круглых флагов, при выборе страны центр показывает флаг, а ниже топ офферов страны. Хвост стран объединяется в «Остальные».
- **Таблица по дням:** 7 строк на страницу, сортировка, итог за период, пагинация.
- **Фильтры в шапке:** страна, период, «Обновить», полноэкранный режим. Выбор страны общий для главной, «По приложениям» и «Google Play» и запоминается в `localStorage`.

### 6.3 Страница «По приложениям»

Карточки приложений в сетке `auto-fit` (минимум 440 px). В карточке: иконка, название и страна, четыре плитки (хосты, клики, конверсии, заработано) с плашками прироста за день и кнопка «Подробнее», раскрывающая полосу дохода и список офферов приложения. Раскрытые карточки запоминаются. Размеры цифр в плитках масштабируются от ширины карточки (container queries), при ширине карточки меньше 480 px плитки перестраиваются в сетку 2×2. Страна приложения берётся из Google Play или `SRC_META`.

### 6.4 Дизайн-система

- Тёмная тема: фон страницы ровный тёмный шоколад (`#060302`). Блоки используют два стиля:
  1. **Тёмное стекло:** градиент от `#0b0705` к `#050302`, мягкие тёплые блики в верхних углах, без рамки (график, офферы, страны, таблица, карточки приложений);
  2. **Свечение снизу:** блок «Заработано» и маленькие плашки: тёплое оранжевое свечение от нижнего края.
- Единое скругление блоков 30 px, малых плиток 22 px.
- Акцент: оранжевый (`#FF6A1A`, `#E9A468` для подписей). Рост за сегодня зелёный (`#34D399`, на плашках мягче `#6fdc9c`), отклонённое красное (`#F87171`).
- Иконки и логотип: столбцы и линия, плитка для телефона и прозрачный знак для вкладки.

### 6.5 Адаптивность

- Ряды главной страницы построены на `flex` с переносом: график растягивается, блок «Заработано» зафиксирован (450 px) и переносится под график при нехватке места. Верхние карточки: 4 в ряд, 2×2 до 1100 px, по одной на телефоне.
- Боковое меню сворачивается в иконки на десктопе и выдвигается кнопкой на телефоне. Группа «Приложения» раскрывается. В свёрнутом режиме показывается только иконка группы.
- На телефоне фильтр страны занимает свою строку, период и «Обновить» стоят рядом. Учтены безопасные зоны (вырез и строка состояния).

### 6.6 PWA и service worker

`sw.js` нужен только для установки на экран «Домой»: он пропускает все запросы в сеть и не кэширует страницы и данные, потому что они защищены паролем. На практике браузер всё равно может держать старую версию страницы, поэтому после выкладки нужна жёсткая перезагрузка (при отладке service worker и кэши сбрасывались вручную).

## 7. Переменные окружения

Полный список с комментариями лежит в `.env.example`. Группы:

| Группа | Переменные |
|---|---|
| Основное | `AFFISE_API_KEY`, `DASH_PASSWORD`, `SESSION_SECRET`, `PORT`, `TIMEZONE`, `AFFISE_BASE` |
| Google (общее) | `GA_SERVICE_ACCOUNT_JSON` / `GA_SERVICE_ACCOUNT_FILE` / `GA_CLIENT_EMAIL` + `GA_PRIVATE_KEY` (суффикс `_<APP>` для отдельных ключей) |
| GA4 по приложениям | `GA_PROPERTY_WONGA`, `_MPOWA`, `_NAVO`, `_UNIFI`, `_KWIK`, `_PRESTOMIN`, `GA_STREAM_IDS_UNIFI` |
| Google Play | `PLAY_PACKAGES`, `PLAY_FLAGS`, `PLAY_RELEASED`, `PLAY_HIDE`, `PLAY_TEST_START`, `PLAY_COUNTRIES` |
| Витрина | `HIDE_OFFERS`, `SRC_APPS`, `SRC_META` |
| Отладка | `GA_MOCK=1` |

Значения секретов в репозиторий не попадают. В Render обязательны `DASH_PASSWORD`, `AFFISE_API_KEY` и (рекомендуется фиксированный) `SESSION_SECRET`.

## 8. Деплой

- `render.yaml`: веб-сервис `profitcash-stats`, runtime Node, без сборки, команда `node server.js`, `healthCheckPath: /login`. `SESSION_SECRET` генерируется автоматически, остальные переменные вводятся вручную.
- Процесс выкладки: коммит и push в `main`, затем на Render автодеплой или Manual Deploy → Deploy latest commit, затем жёсткое обновление страницы.
- Только HTTPS. Статический хостинг (GitHub Pages, Firebase Hosting) не подходит, так как нужен серверный пароль и прокси к Affise.

## 9. Локальная разработка

```bash
cp .env.example .env     # заполнить DASH_PASSWORD, AFFISE_API_KEY, при необходимости ключи Google
node server.js           # http://localhost:3000
```

- Без `AFFISE_API_KEY` отдаются демо-данные.
- Сервер намеренно не пускает при пустом пароле. Для локального просмотра «без ввода пароля» использовался небольшой прокси, который подставляет cookie сессии, а сам сервер запускался с временным паролем. Сам код авторизации ради этого не менялся.
- После правок кода сервер нужно перезапускать (`node` не следит за файлами). Правки `public/index.html` подхватываются перезагрузкой страницы, но service worker и кэш лучше сбросить.
- Проверка JS без браузера: `new Function(...)` над содержимым `<script>` ловит синтаксические ошибки.

## 10. Как добавить новое приложение

1. **Метка в ссылках.** В Remote Config приложения в каждую ссылку оффера добавить `&sub1=<метка>` (нижний регистр). Для ссылок не `lead-cash.com` (например `go.goodaff.eu`) формат параметра нужно уточнить отдельно.
2. **Страница «По приложениям».** Добавить `метка=пакет` в `SRC_APPS` (в коде по умолчанию и, если переменная задана, в Render) и название в `SRCN` в `index.html`, если приложения нет в Play.
3. **Аналитика (по желанию).** Добавить запись в `APPS` в `ga.js` (`findByName` по имени Firebase-проекта или `propertyId`), пункт меню и название в `APPN`.
4. **Google Play (по желанию).** Добавить пакет в `PLAY_PACKAGES` и при необходимости страну в `PLAY_COUNTRIES`.

## 11. Известные особенности и грабли

- **Переменные Render перекрывают код.** `SRC_APPS`, `SRC_META`, `HIDE_OFFERS` в Render имеют приоритет над значениями по умолчанию.
- **Конверсии включают отклонённые.** Отклонённые считаются в «Конверсиях», но отмечаются красным в приросте за день.
- **Баланс живой.** API и кабинет могут расходиться по времени. Дашборд берёт «доступно».
- **Приоритет CSS.** В файле накопилось много слоёв оформления с `!important`. Старое правило `#cards>.card:not(.d)` перебивало новые стили карточек. Новые правила нужно писать с равным или большим приоритетом и дописывать в конец `<style>`.
- **Слои бликов.** Глобальные правила рисуют кольцо-рамку через `::after` с маской. Для блоков без рамки этот слой надо отключать явно.
- **Service worker.** После выкладки может остаться старая версия страницы (нужна жёсткая перезагрузка).
- **Правки большого CSS-блока.** При автоматической замене текста легко вырезать лишнее (так однажды были потеряны стили). Перед массовой заменой стоит делать копию файла.
- **Часовой пояс.** «Сегодня» определяется по часовому поясу кабинета (`Indian/Kerguelen`), а не браузера.

## 13. Безопасность

- Пароль сравнивается без утечки по времени, перебор ограничен (5 попыток в минуту с IP).
- Cookie `HttpOnly`, `SameSite=Lax`, `Secure` за HTTPS-прокси. Токен подписан HMAC.
- Ключи Affise и Google хранятся только в переменных окружения сервера. `.env` и файлы `*.env.md` в git игнорируются.
- Внешний `fetch` идёт только на доверенные хосты (Affise, Google, страницы Play).
- В репозиторий не нужно класть ключи сервисных аккаунтов и значения секретов, даже в примеры.
